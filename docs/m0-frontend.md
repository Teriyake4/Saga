# M0 frontend/workload-input evidence

`bench/reference/frontend-lock.json` records the exact pinned Hugging Face revisions, HTTPS resolve URLs and final URLs, byte sizes, and SHA-256 for the actual downloaded JSON/template inputs. The corresponding local files are intentionally untracked under `.cache/m0-frontend/`. Only `config.json`, `tokenizer.json`, `tokenizer_config.json`, `chat_template.jinja`, and `generation_config.json` were acquired. No weights were downloaded and no model-provided code was run.

Run offline after acquiring the files (from the project root):

```sh
.cache/m0-frontend/venv/bin/python tools/m0_frontend.py --compare --workload bench/workloads/plain-128.json --workload bench/workloads/plain-2048.json --workload bench/workloads/native-mtp-7680.json --output-dir .cache/m0-frontend/results
```

The tool checks every locked file's size and SHA-256 before parsing, rejects traversal and symlinks in locked local paths, and rejects unsafe candidate IDs. It uses the Rust `tokenizers` JSON tokenizer and `ImmutableSandboxedEnvironment` with Jinja's default undefined behavior (matching the relevant HF Jinja environment behavior; no StrictUndefined parity is claimed), plus a provided `raise_exception` helper. The tokenizer BOS/EOS strings come from the pinned tokenizer/config bindings. Every workload explicitly fixes date, empty tools/documents, generation-prompt setting, `enable_thinking`, `reasoning_effort: xhigh`, `preserve_thinking`, and `add_vision_id`; validation accepts only the pinned template's supported `low`, `medium`, and `xhigh` reasoning-effort values. Empty tool/document arrays therefore have explicit semantics. Actual output hashes, prompt/token-ID digests, and observed counts are indexed in `bench/workloads/frontend-input-evidence.json`; it expressly remains non-mandatory and UNFROZEN. The comparison plus all three actual rendered-text/token-ID JSON outputs are checked in under `bench/workloads/inputs/`, so exact prompt inputs can be reused without the local `.cache` artifacts (including on Windows). The index and stdlib tests validate those tracked bytes and counts. The builder adjusts a single text message using deterministic ` x` filler with a bounded search (targets 1–32,768); it errors rather than returning a false/approximate match if the exact requested count cannot be reached. Output reserves are also type-checked and bounded (1–8,192 tokens). On this captured run, the three candidates matched 128, 2,048, and 7,680 prompt tokens; all use a 512-token output reserve, for totals of 640, 2,560, and 8,192. These are artifact-specific frontend candidates that may be reused for plain or native-MTP input testing; they are not a complete workload definition, runtime measurement, or suite freeze.

The original and GSQ revisions share byte-identical tokenizer JSON, tokenizer configuration, and chat template; both tokenizer JSON vocab sizes (248,077) and config-declared text vocab sizes (248,320) plus special-token bindings are compared. Configuration geometry and each differing generation-config field/value (including GSQ-only `min_p`, `presence_penalty`, and `repetition_penalty`) are reported; geometry differences are not a claim of full component compatibility. Tokenizer byte identity plus local `tokenizers` output is useful frontend evidence, not proof of compatibility with every runtime's special-token handling or any model weights. This does not establish dispatch, MTP-head/weight availability or correctness, generation behavior, sampling, speed, or quality. M0 suite remains **UNFROZEN**; frontend inputs alone must not become a mandatory frozen comparison. The optional project-local environment pins `tokenizers==0.22.1` and `Jinja2==3.1.6` and is not installed globally. `.cache/m0-frontend/requirements.lock` records all captured transitive requirements with wheel SHA-256 hashes; `frontend-lock.json` records that lock file's hash. To reproduce the environment from the captured cache, use `python3 -m venv .cache/m0-frontend/venv` followed by `.cache/m0-frontend/venv/bin/python -m pip install --no-index --find-links .cache/m0-frontend/wheelhouse --require-hashes -r .cache/m0-frontend/requirements.lock`. The wheelhouse/lock are specific to the captured macOS arm64/Python 3.9 environment, not a universal cross-platform dependency solution.
